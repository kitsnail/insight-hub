# Insight Hub 功能路线图

> 记录未来功能规划与方案讨论，逐步演进

---

## 功能规划概览

| 优先级 | 功能 | 状态 | 说明 |
|--------|------|------|------|
| P0 | Markdown 渲染 | 设计中 | 基础能力缺失，影响所有文本内容 |
| P1 | 任务看板 | 规划中 | 高频使用场景，提升效率明显 |
| P1 | 图表展示 | 规划中 | 数据价值可视化，增强洞察 |

| P3 | AI 辅助分析 | 规划中 | 锦上添花，可后期引入 |
| P3 | 知识图谱 | 规划中 | 高级功能，架构复杂 |

## 1. Markdown 渲染能力

### 当前状态

❌ 不具备。当前实现只是简单展示纯文本：

```html
<p class="text-gray-300 whitespace-pre-wrap">${item.content || ''}</p>
```

### 影响

- 笔记、文档类内容无法展示格式化效果
- 代码块没有语法高亮
- 表格、列表等结构化内容显示混乱
- 链接无法点击

### 方案选项

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **marked.js** | 轻量、成熟、CDN可用 | 无语法高亮 | 基础需求 |
| **marked + highlight.js** | 轻量 + 语法高亮 | 需要两个库 | 代码笔记 |
| **markdown-it** | 插件丰富、可扩展 | 稍重 | 高级定制 |
| **服务端渲染** | SEO友好、一致性好 | 增加后端复杂度 | 公开内容 |

### 倾向方案

`marked.js + highlight.js`（CDN 引入，零后端改动）

### 详细设计

→ 见 [markdown-rendering-design.md](./markdown-rendering-design.md)

## 2. 日常任务管理（看板、列表）

### 当前状态

⚠️ 仅列表，无任务特化

**现有能力：**
- ✅ 基础列表视图（卡片网格）
- ✅ 筛选（类型、来源、标签、状态）
- ✅ 排序（时间、标题）
- ✅ 批量操作

**缺失能力：**
- ❌ 看板视图（Kanban）
- ❌ 任务状态流转（todo → in_progress → done）
- ❌ 任务截止日期
- ❌ 任务进度追踪
- ❌ 子任务支持

### 方案分析

#### 方案 A：轻量扩展（推荐）

在现有架构上扩展，添加 `task` 类型的特化展示：

```json
{
  "type": "task",
  "metadata": {
    "status": "todo | in_progress | done | blocked",
    "priority": "P0 | P1 | P2 | P3",
    "due_date": "2026-03-10",
    "progress": 60,
    "assignee": "kitsnail",
    "parent_id": null,
    "checklist": [
      {"text": "完成设计", "done": true},
      {"text": "实现功能", "done": false}
    ]
  }
}
```

**UI 扩展：**
1. **看板视图** - 按 `metadata.status` 分列展示
2. **任务详情增强** - 进度条、Checklist、截止日期倒计时
3. **状态流转** - 拖拽或按钮切换状态

#### 方案 B：独立任务模块

创建独立的 `tasks` 表，与 `items` 分离。

**优点：** 任务特化、关系清晰
**缺点：** 架构复杂、数据割裂

### 倾向方案

**方案 A** — 利用现有 metadata 灵活性，前端增强展示

## 3. 数据分析、搜索、图表展示

### 当前状态

⚠️ 基础统计，无图表

**现有能力：**
- ✅ 统计 API（`/api/v1/stats`）
- ✅ 全文搜索（PostgreSQL `tsvector`）
- ✅ 标签过滤

**缺失能力：**
- ❌ 时间趋势图表
- ❌ 标签关联分析
- ❌ 来源分布饼图
- ❌ 词云
- ❌ 高级搜索（组合条件、范围查询）

### 搜索增强方案

| 功能 | 实现方式 | 复杂度 |
|------|---------|--------|
| 高级搜索表单 | 前端组合查询参数 | 低 |
| 时间范围筛选 | API 添加 `start_date`, `end_date` | 低 |
| 组合条件 | API 支持多条件 AND/OR | 中 |
| 保存搜索 | 存储为 `type=search` 的 item | 低 |
| 搜索建议 | 前端缓存标签/类型 | 低 |

### 图表展示方案

| 图表类型 | 数据源 | 库选择 |
|---------|--------|--------|
| 时间趋势 | `by_date` | Chart.js / ECharts |
| 类型分布 | `by_type` | 饼图 |
| 标签云 | `by_tag` | 现有实现可优化 |
| 来源分布 | `by_source_system` | 柱状图 |
| 热力图 | 按小时/星期统计 | 需新增 API |

### 倾向方案

1. **Chart.js** — 轻量、CDN 可用、文档友好
2. **API 扩展** — 添加时间序列数据端点
3. **Dashboard 页面** — 独立的数据分析视图

## 4. 价值挖掘、经验总结、问题发现

### 当前状态

❌ 不支持

这是最高阶的需求，需要从数据中"提炼"出价值。

**核心问题：** Insight Hub 目前是 **存储** 系统，不是 **分析** 系统。

### 方案分析

#### 方案 A：AI 辅助分析

引入 AI 能力，对数据进行智能分析：

```
功能模块：
├── 自动摘要 - 对长内容生成摘要
├── 关键词提取 - 自动打标签
├── 关联发现 - 发现数据间的隐含关系
├── 趋势分析 - 识别追踪话题的发展趋势
├── 异常检测 - 发现异常数据点
└── 报告生成 - 定期生成洞察报告
```

**实现方式：**
1. **本地 LLM** — Ollama + 小模型（隐私好，成本高）
2. **云端 API** — OpenAI / Claude API（简单，有成本）
3. **规则引擎** — 基于规则的分析（无 AI 成本，能力有限）

#### 方案 B：结构化沉淀

建立知识管理流程：

```
数据流向：
原始数据 → 整理归类 → 提取洞察 → 形成文档 → 持续迭代

文档类型：
├── 周报/月报 - 汇总统计 + 关键事件
├── 技术笔记 - 踩坑 + 解决方案
├── 决策记录 - ADR (Architecture Decision Records)
├── 经验总结 - 最佳实践
└── 问题追踪 - 待解决问题清单
```

#### 方案 C：知识图谱

构建数据间的关联关系：

```
节点：Item（数据项）
边：
  ├── 引用关系 - A 引用了 B
  ├── 从属关系 - A 是 B 的子任务
  ├── 关联关系 - A 和 B 话题相关
  └── 演化关系 - A 是 B 的后续发展

应用：
  - 可视化展示数据网络
  - 发现关键节点（被引用最多）
  - 发现孤立数据（未关联）
  - 推荐相关内容
```

### 推荐路线

```
Phase 1: 结构化沉淀
├── 定义文档类型模板
├── 建立标签体系
└── 手动整理流程

Phase 2: AI 辅助
├── 接入 LLM API
├── 自动摘要/标签
└── 智能搜索

Phase 3: 知识图谱
├── 数据关联建模
├── 图数据库（可选）
└── 可视化展示
```
